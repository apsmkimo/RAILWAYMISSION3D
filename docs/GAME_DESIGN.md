# RAILWAY MISSION 3D：完整開發企劃

> 設定：風格 realistic（寫實）｜玩法 mission（任務）｜平台 Android｜開發規模 solo（個人開發）
> 第一版決定：寫實操作（油門、煞車分開）｜駕駛室＋外部視角可切換｜第一台火車：現代電聯車｜引擎：Unity 6 + C#

**寫實 3D 火車任務駕駛模擬遊戲。** 玩家扮演火車駕駛員，完成乘客運輸、準時抵達、貨物運送、緊急煞車等任務，逐步解鎖新火車與新鐵路路線。

核心原則：**先做一款小而精緻的火車任務遊戲，不要一開始就挑戰大型開放世界。** 這比較符合個人開發的時間、技術與 Android 手機效能限制，也更容易做出可以上架 Google Play 的產品。

### 3 星評分系統

每次任務結束後依表現評分：時間（是否準時到達）、停靠（是否停在正確位置）、安全（是否超速或違規）、操作（是否平穩加速、減速）。
範例：準時抵達 +300、精準停靠 +300、安全駕駛 +200 → 獲得金幣 800。

## 四、駕駛操作介面 UI

橫向全螢幕，畫面以駕駛室或火車外部視角為主。

- 油門：0～100%
- 煞車：0～100%
- 緊急煞車：獨立按鈕
- 喇叭：獨立按鈕
- 攝影機：三種視角切換
- 速度表：即時顯示速度及限速
- 上方顯示下一站與距離進度

精準停靠設計成有月台停止區間，讓玩家需要提前判斷煞車距離，而不是進站才突然按煞車。

### 3. 火車移動系統（最重要）

採用 **Spline 路徑 + 自訂火車物理運算**，不讓火車依靠一般物理碰撞自由行駛。

- 速度：v_new = v_old + a·Δt
- 位置：P = Spline(s)，s 為沿鐵軌累積的行駛距離
- 物理因素：油門輸出、煞車力量、火車重量、行駛阻力、軌道坡度、彎道與車體方向、最大速度

初期將整列火車視為一個運動物件，車廂沿著前方車廂的路徑位置依序跟隨。

## 六、任務資料與程式設計

使用 Unity `ScriptableObject` 定義任務（任務名稱、說明、起訖車站、速限、時間限制、停車容許誤差、獎勵、難度），新增任務只需建立新的 MissionData。

MissionManager 流程：載入任務 → 初始化火車 → 啟動計時 → 監測行駛速度 → 監測停靠位置 → 判斷是否違規 → 判斷是否抵達終點 → 計算任務評分。

## 七、Android 效能最佳化

| 項目 | 建議 |
|---|---|
| 渲染管線 | URP |
| 目標 FPS | 30～60 |
| 解析度 | 動態解析度 |
| 陰影 | 中低品質 |
| 遠景 | LOD |
| 建築 | GPU Instancing |
| 地形 | 分區載入 |
| 光照 | 預烘焙為主 |
| 特效 | 控制粒子數量 |
| 貼圖 | 依距離調整解析度 |

1. 不要一次載入整張地圖。
2. 不要讓所有乘客都是高精度模型。
3. 火車物理與畫面分開（物理不綁定畫面更新頻率）。

## 八、遊戲商業模式

| 項目 | 收益方式 |
|---|---|
| 基礎任務 | 免費 |
| 額外任務包 | 付費解鎖 |
| 特殊火車 | 金幣或內購 |
| 看廣告領取獎勵 | 選擇性廣告 |
| 移除廣告 | 一次性購買 |

不要在行駛過程中跳出全螢幕廣告；在任務完成畫面提供選擇性獎勵廣告。差異化定位：「任務挑戰、精準停靠、寫實駕駛」。

## 九、個人開發時程

1. 第 1～2 週：基礎原型（Unity 專案、3D 火車、直線及彎道鐵軌、基本加減速）

## 十、第一個可玩版本 MVP：任務 01「首次列車駕駛」

場景：一條長約 3 公里的山區鐵路。玩家需要：啟動火車 → 將速度提升至 60 km/h → 維持安全速度 → 通過一座鐵路橋梁 → 進入隧道 → 抵達車站 → 精準停靠月台。完成條件：抵達終點，獲得任務評分。

Demo 只需要：一台火車模型、一條完整鐵軌、一個車站、一套駕駛 UI、一套火車物理系統、一套任務判斷系統。
